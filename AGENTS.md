# AGENTS.md: Overview

A read-only monitor of every coding-agent session (Orca, Claude Code, Codex, SSH hosts), drawn as an isometric world of islands, plots and creatures, with a ranked attention list and a task tracker. Read `PRODUCT.md` first, then `docs/PLAN.md`.

## Local first: no artifacts

- The files in this folder and in `../signal` are the only source of truth.
- Do **not** publish this work as claude.ai artifacts, Claude Docs or any other account-bound page. The owner switches between several Claude accounts, and one of them ("dev") is shared with other people. Ask first before anything leaves this machine.
- To show work, run `./serve.sh` (the local hub at http://localhost:4173/overview/), or capture screenshots with headless Chrome into `.impeccable/review/`.

## Design system

Overview's look comes from **Signal** (`../signal`, package `@barrymind/signal`), which is shared with Hangar and future apps:
- Change a colour, size or component in Signal (`tokens/*.json`, `css/components.css`), never in Overview, then run `./scripts/sync-signal.sh`. The app's markup uses Signal's `.sg-*` classes; `app/web/app.css` holds only Overview's own layout (title bar, map stage, rail, settings page) and reads `--sg-*` tokens directly.
- Map-only values go in Signal's Overview extension, `../signal/tokens/extensions/overview.tokens.json`.
- The design rules: colour only for status and for "you", monochrome graphite everywhere else, mono for machine text and sans for prose, hairlines and small radii.

## Stack

- Rust + Tauri 2 (`app/`), plain HTML/JS front end (`app/web/`, no build step). Why: one small native binary per OS that can read local files and run `ps`/`ssh` without a server.
- One Cargo workspace at the root (`Cargo.toml`): members `app/core` and `app/src-tauri`, one `Cargo.lock`, one `target/`. The version lives only in `[workspace.package]`; `tauri.conf.json` has no version, so Tauri takes the crate's (R4.2).
- Toolchain pinned in `rust-toolchain.toml`.

## Checks and releases

- `scripts/check`: `cargo fmt --check`, `clippy -D warnings`, `cargo test` for the workspace. The prototypes' `npm test` runs are not part of it (history, not shipped).
- Targets are the owner's machines only: macOS (Apple silicon) and Linux on a Wayland compositor. No distro packages (.deb, .rpm): Linux ships one AppImage, which runs on any distro. Ubuntu appears only as the GitHub runner that builds it.
- `scripts/build`: Linux gives the AppImage through the Tauri CLI (pinned `@tauri-apps/cli` version, run with npx); macOS gives a zipped, unsigned `.app`. The Release workflow builds both (macOS and Ubuntu runners) and attaches them to one draft release.
- CI and Release install WebKitGTK on the Linux runner before compiling, because Tauri links against them.

## Known Linux gaps (alpha)

- Reading sessions, ssh machines and summaries (key through `secret-tool`) work on Linux.
- "Go to session" on Linux: Hyprland only (detected by `HYPRLAND_INSTANCE_SIGNATURE`). The window is found by walking up from the agent's pid to the nearest ancestor that owns a window in `hyprctl clients -j` (`procs::window_owner`), then `hyprctl dispatch 'hl.dsp.focus({ window = "pid:<owner>" })'` (Hyprland 0.56+ with a Lua config, which the owner runs; measured 2026-11-06 on `workstation`, Hyprland 0.56.2: prints `ok` and focuses the window), falling back to the classic `hyprctl dispatch focuswindow pid:<owner>`. When no ancestor owns a window (measured 2026-11-06 on `workstation`: every Orca session runs under its detached `~/.orca-remote` node helper, herdr ones under `herdr-core` from systemd), the window whose class names the same program as the host is used (`procs::window_by_name`, the same first-word rule as `installed_bundle` on macOS: `orca-remote` -> class `orca`). On Linux, hosts are named from `/proc/<pid>/exe` when a process renamed itself (`MainThread`). A terminal that runs many windows from one process gets one of them focused. A session in tmux has no window. Other Wayland compositors get an error until the owner uses one.
- Resume and remote shells open the owner's terminal through `xdg-terminal-exec`, else `$TERMINAL -e`, else `x-terminal-emulator`. Not yet tried on the owner's Hyprland machine.

Every agent follows the shared rules in `.toolkit/RULES.md` (managed by jb-toolkit); deliberate exceptions are in `.jb-exceptions`.
